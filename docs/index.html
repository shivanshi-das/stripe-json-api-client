JSON API Client

A small Python client that requests a list of HTTP endpoints and reports each one's path, status code and decoded JSON body, in the order asked.

View the code on GitHub

What it does

fetch_endpoints(base_url, paths) sends one GET request per path and returns one result per path. Repeated paths are requested again, input order is kept, and an error response keeps its status and body instead of raising. An empty list makes no requests.

The client

import requests

def fetch_endpoints(base_url, paths):
    responses = []
    for path in paths:
        response = requests.get(f"{base_url}{path}")
        responses.append({
            "path": path,
            "status": response.status_code,
            "body": response.json(),
        })
    return responses

The fixture service

A local FastAPI app supplies three endpoints to call, plus a POST /fetch controller that runs the client and records which fixture paths were actually hit.

EndpointStatusBody
/fixture/record200{"label": "hello", "count": 7}
/fixture/list200[1, 2, 3]
/fixture/missing404{"error": "missing"}

Example

POST /fetch
{"paths": ["/fixture/missing", "/fixture/record"]}

{
  "responses": [
    {"path": "/fixture/missing", "status": 404, "body": {"error": "missing"}},
    {"path": "/fixture/record",  "status": 200, "body": {"label": "hello", "count": 7}}
  ],
  "requested_paths": ["/fixture/missing", "/fixture/record"]
}

Run it locally

python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest -v

pytest starts the fixture service on 127.0.0.1:8765 for the test session. The suite covers:

  • object and array JSON bodies
  • repeated paths, input order and the preserved 404 body
  • an empty path list, through the API and directly
